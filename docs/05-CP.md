## 三种切法

```
(1) cp_qk —— 切 Q 也切 KV（经典 CP / ring attention）

    rank0: q[0:c]  kv[0:c]        ┌── 转 (N-1) 轮补齐 KV ──┐
    rank1: q[c:2c] kv[c:2c]  ==>  │ send → rank+1           │
    rank2: q[2c:3c] ...           │ recv ← rank-1           │
    rank3: ...                    └────────────────────────┘

(2) zigzag —— 在 (1) 之上把块配对

    rank0: 第0块 + 第(2N-1)块
    rank1: 第1块 + 第(2N-2)块
    通信同 (1)，但失衡被压平

(3) cp_q —— 只切 Q，KV 每卡一份全量

    rank0: q[0:c]  +  全量 KV
    rank1: q[c:2c] +  全量 KV
    通信：0
```

## 三条判据对应的三个结论

| 判据 | 结论 |
| --- | --- |
| 归约代数 | 纯加（HSTU/MTGR）⇒ 分块求和精确，**零归约**；softmax（LONGER）⇒ 需要 LSE 合并 |
| 掩码拓扑 | 方阵 ⇒ 失衡 1.00；因果 ⇒ 2−1/N；zigzag ⇒ 1.00（代价：重排 kernel） |
| 单卡容量 | N≤32K 时 KV ≈ 1 GB ⇒ 装得下 ⇒ **不需要切** |

## 实测（`parallel/cp_min.py` 跑出来的数）

因果掩码、N 张卡、误差指相对单卡的 `max_abs_err`：

| N | cp_q 失衡 | cp_qk 失衡 | zigzag 失衡 | cp_q 通信 | cp_qk 通信 | 误差 |
| --- | --- | --- | --- | --- | --- | --- |
| 2 | 1.50 | 1.50 | 1.00 | 0 | 64 KiB | 0 |
| 4 | 1.75 | 1.75 | 1.00 | 0 | 96 KiB | 2.8e-16 |
| 8 | 1.87 | 1.87 | 1.00 | 0 | 112 KiB | 2.2e-16 |

三条读数：

1. **cp_q 与 cp_qk 的失衡相同** —— 都是 `2 − 1/N`。它们的区别不是 pair 数，是**通信**。
2. **zigzag 把失衡压到 1.00**，代价是块重排的 kernel。
3. **cp_q 的通信恒为 0，且结果精确到浮点误差**。

## cp_q 的代价：多读的那份 KV

`cp_q` 每卡要读**全量** KV，所以：

```
cp_q  多读  (1 − 1/N)·P·κ     来自 HBM      ~800 GB/s
cp_qk 通信  (1 − 1/N)·P·κ     走互联        ~200 GB/s
                ↑
           字节数完全相同
```

**两边的字节数一模一样，胜负只取决于用哪种带宽。**
HBM : 互联 ≈ 4 : 1 ⇒ cp_q 恒定赢 4 倍，与 P、N 无关。

> 这就是 Medha 的 KVP 在结构上占优的真正原因：不是「更聪明的算法」，
> 而是**把同样的搬运量从慢带宽挪到了快带宽**。

## 场景 2：decode 时 q = B

| B | P | cp_q 每卡读 | 每 query 摊到 | pair/步 |
| --- | --- | --- | --- | --- |
| 1 | 4096 | 1024 KiB | **1024 KiB** | 0.004 M |
| 128 | 4096 | 1024 KiB | 8 KiB | 0.52 M |
| 512 | 4096 | 1024 KiB | **2 KiB** | 2.10 M |
| 900 | 32768 | 8192 KiB | 9.1 KiB | 29.5 M |

第 3 列与 B 无关（这是 cp_q 的固定代价），但**第 4 列按 1/B 摊薄**。

`B=1` 时（LLM decode）摊不开 ⇒ cp_q 永远不划算。
`B=512` 时（GR decode）摊得开 ⇒ cp_q 开始有意义。

## 什么时候必须用 cp_qk

| 条件 | 选择 | 理由 |
| --- | --- | --- |
| KV 单卡装得下 | **cp_q** | 零通信、精确、无重排 |
| KV 单卡装不下（L > 32K） | cp_qk | 只能切，通信是硬代价 |
| 有 softmax（LONGER） | 都必须 | 需要 online softmax，归约不再是加法 |
| q 很小（LONGER 的 50~250） | cp_q 也不划算 | 省下的绝对工作量本来就小 |

## 为什么 LONGER 是例外

LONGER 的注意力有 softmax，而且 `q : L ≈ 1 : 40 ~ 1 : 100`：

- softmax ⇒ 必须 online softmax，跨卡要合并 `(max, sum)`
- q 只有 50~250 ⇒ `q·L` 本来就小 ⇒ Amdahl 上限只有 1.2~1.3×

这两条合起来造成一个尴尬的事实：
**唯一真正需要长序列的模型（LONGER），是唯一需要复杂 CP 的模型；
而 CP 很简单的模型（HSTU），是唯一不需要长序列的。**

## 常见误解

| 误解 | 修正 |
| --- | --- |
| 「ring 是唯一的 CP 实现」 | cp_q（复制 KV）通信为 0，在 KV 装得下时严格更优 |
| 「zigzag 总是更好」 | 它只在**因果**掩码下有用；方阵（MTGR 静态段）下是负优化 |
| 「失衡 2−1/N 又不大」 | 它是**计算项**的失衡；当固定开销占 90% 时，修它只值 1~3% |
| 「CP 省通信 ⇒ 值得做」 | 通信下界 Θ(Ldh) 已封死；决定成败的是有没有工作量可省 |
| 「加卡就该更快」 | 固定开销 ∝ N ⇒ 短序列上加卡是**变慢**（内点现象） |

## 三个可以直接算的判据

**判据 A（要不要切）**

```
KV 字节 = L · d · 2 · 2 · 层数
L=32K, d=512, bf16, 32 层  →  1.0 GB
一张 910B = 64 GB  →  装得下  →  不切
```

**判据 B（切了值不值）**

```
Amdahl 上限 = T(1) / T(∞)
只在计算项占比 > 50% 时才有意义
```

**判据 C（cp_q 还是 cp_qk）**

```
KV 装得下      → cp_q
KV 装不下      → cp_qk
有 softmax     → 两者都要 LSE 合并，先看 q/L
```
